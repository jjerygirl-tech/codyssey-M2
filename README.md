## 설계 설명

### 기본 문제 수

`quiz.py`의 `create_default_quizzes()` 함수에서 기본 퀴즈 5개를 생성합니다.
`test_quiz.py`에서는 기본 문제가 5개 이상이고, 모든 문제가 보기 4개와 정답 번호를 갖는지 확인합니다.

### 클래스 사용 이유

`Quiz` 클래스는 문제, 보기, 정답, 힌트처럼 한 퀴즈에 속한 데이터를 묶습니다.
`QuizGame` 클래스는 여러 퀴즈의 출제·점수·삭제를 관리합니다.
함수만 사용하는 것보다 데이터와 관련 동작을 한 객체에 묶을 수 있어 역할을 분리하고 기능을 확장하기 쉽습니다.

### 책임 분리

- `QuizGame`: 사용자 입력 검증, 게임 진행, 점수 계산
- `Storage`: JSON 파일 읽기·쓰기, 데이터 구조 검증, 백업·복구
- `Quiz`: 퀴즈 하나의 데이터와 정답 판정

입력 검증은 사용자의 입력을 프로그램에서 사용할 값으로 바꾸는 책임이고,
데이터 입출력은 변환된 데이터를 `state.json`에 저장하고 복원하는 책임입니다.

### 데이터 흐름

1. 프로그램 시작
2. `Storage.load()`가 `state.json`을 읽음
3. 문제가 없거나 손상되면 기본 퀴즈 또는 백업 파일을 사용
4. 게임에서 퀴즈·점수·기록을 변경
5. 퀴즈 추가, 삭제, 풀이 종료 시 `Storage.save()` 호출
6. 저장 전에 기존 파일을 `state.json.bak`으로 백업

### JSON 설계 이유

JSON은 사람이 직접 읽을 수 있고, 리스트와 딕셔너리 같은 구조를 표현하기 쉽습니다.
현재는 퀴즈·최고 점수·히스토리를 하나의 문서 안에 저장하고 있어 기능을 추가하기도 쉽습니다.

### 손상 파일 복구

`state.json`을 읽을 수 없으면 손상된 원본을 `state.json.corrupt.bak`으로 보관합니다.
그 다음 `state.json.bak`을 읽어 복구하고, 백업도 사용할 수 없을 때만 기본 퀴즈로 초기화합니다.

### JSON 방식의 한계

현재 방식은 저장할 때 JSON 파일 전체를 다시 씁니다.
퀴즈와 기록이 수백~수천 개 수준으로 커지면 파일 읽기·쓰기 시간이 늘어나고 메모리 사용량도 증가할 수 있습니다.
대규모 데이터가 필요해지면 SQLite나 다른 데이터베이스로 변경하는 것이 적절합니다.

## Git 브랜치와 커밋 전략

`feature/add-quiz` 브랜치는 퀴즈 추가 기능을 `main`과 분리해 개발하기 위해 만들었습니다.
기능을 확인한 뒤 `main`에 병합하면 작업 중인 변경과 안정된 코드를 구분할 수 있습니다.

커밋 메시지는 변경 종류와 내용을 함께 작성했습니다.

```text
Feat: 기능 추가
Fix: 오류 수정
Refactor: 코드 구조 개선
Test: 테스트 추가
Docs: 문서 또는 증빙 추가
Data: 저장 데이터 변경
Merge: 브랜치 병합
